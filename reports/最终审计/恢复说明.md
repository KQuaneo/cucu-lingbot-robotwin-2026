## 6. DCP 续训的准确入口

旧 `run.sh` 只是训练启动记录，**不能直接作为续训命令**。`training/train_full_sft.sh` 写死了 `--train.enable_resume false`，没有传入 `load_checkpoint_path` 的环境变量入口。

源码确认的恢复参数是 `--train.load_checkpoint_path`，可同时显式开启 `--train.enable_resume true`。`tasks.vla.train_lingbotvla` 会恢复模型、优化器和 `extra_state`，包括 global step、scheduler、dataloader、environ meter 和 torch RNG。恢复入口示例：

```bash
export AITER_TRITON_ONLY=1
export FLASH_ATTENTION_TRITON_AMD_ENABLE=TRUE
export HIP_VISIBLE_DEVICES=0,1,2,3,4,5,6,7
unset ROCR_VISIBLE_DEVICES CUDA_VISIBLE_DEVICES
export TMPDIR=/var/tmp/robotwin-resume-cache
mkdir -p "$TMPDIR"
cd /RoboTwin/experiments/lingbot_vla_v2_6b_robotwin/source/lingbot-vla-v2
/opt/robotwin-env/bin/python -m torch.distributed.run \
  --standalone --nproc-per-node=8 -m tasks.vla.train_lingbotvla \
  /workspace/restore/full_sft_6000/lingbotvla_cli.yaml \
  --train.load_checkpoint_path /workspace/restore/global_step_6000 \
  --train.enable_resume true --train.allow_partial_checkpoint false \
  --train.resume_dataloader_state true \
  --train.output_dir /workspace/runtime/outputs/resume_checked \
  --train.max_steps 10000 --train.save_steps 1000
```

示例中的 `max_steps=10000` 表示**总步数** 10k，从 6k 继续约 4k，并非再训练 10k。这是下一阶段可审阅的入口方案，尚未运行；配置副本应先修正路径，并重新决定学习率日程。

初次恢复保持原配方：Full-SFT、`TEACHER_MODE=full` 对应 YAML 的完整 teacher 配置、AdamW、8 卡 FSDP2 full shard、micro batch 16、累积 2、global batch 256、gradient checkpointing，视觉编码器不冻结。不改变网络结构、参数组、teacher 开关或数据顺序。

### 必须检查的实际恢复行为

1. 日志明确出现 `Load distributed checkpoint from ... successfully!`，读入 `global_step=6000`，第一步应为 6001。
2. **不能出现 `Starting training from scratch`**。源码会捕获 checkpoint 加载错误并回退到从零训练，而不保证立即退出。
3. **不能出现 `Skip loading Optimizer from ...`**。`lingbotvla/checkpoint/checkpointer.py:436–445` 对优化器加载失败只写提示；随后还可能打印 checkpoint 加载成功。应额外确认 AdamW state 非空、参数组符合原配置。
4. loss、梯度和 LR 应为有限值；确认数据加载恢复没有重复读取错误或路径不匹配。
5. 输出写新目录；保留原始 6k DCP，完成一个续训 step 及新 checkpoint 保存后再考虑长训练。

本次只做了 CPU 安全解析：8 个 `extra_state_rank_*.pt` 均可 `torch.load(..., map_location='cpu', weights_only=True)`，全部 `global_step=6000`。**尚未在新机器加载全部 DCP 模型／优化器并执行 step 6001。** SHA256 通过证明备份与远端一致，不能替代恢复冒烟。

### 延长训练会改变学习率日程

源码先按新的 `max_steps` 建 scheduler，再加载原 scheduler 状态。cosine 的闭包使用新的总步数；将 6k 改到 10k/30k 会重新解释剩余日程，因此不是把原 6k 曲线简单接长。

已解析存档：scheduler `last_epoch=6000`；主参数组最后 LR `5e-5`，MoE 专家组约 `1.4142e-4`，其初始 LR 分别为 `1e-4` 和约 `2.8284e-4`。恢复时选择新总步数、新日程前应明确是否接受 LR 回升，或另行设计从当前 LR 连续衰减的续训日程；不要只修改 `MAX_STEPS` 就把它当作严格连续续训。
