# put_object_cabinet 左右增强审计

Material Passport：2026-10-06；阶段：代码与已有记录审计；状态：ANALYZED，未做仿真复现。输入为引用聊天可访问的附件、项目镜像中的评测代码/日志/数据元信息，及官方当前源码。官方当前源码不等同于实验时 commit。

## 结论

方案方向合理：移动场景后重规划、重执行、重采集，比直接翻转图像并猜测关节符号更可靠。但不能认定已正确修复“刷新 bug”，也不能认定生成数据已通过完整物理和训练接口验收。当前实现应称为“对侧场景重采集 + 修改后的专家策略”。

可访问附件包括两份相同 README、两份安装器、三个校验清单和三个采集/增强脚本。完整 augmentations 包、generation_report/attempts/manifest、增强 HDF5/视频和增强后的闭环成绩未出现在可访问材料中。README 的测试通过陈述属于作者报告，不能替代实际输出。保存的五个正文文件 SHA-256 均与 SHA256SUMS 对应条目一致；这验证版本身份，不验证运行正确性。

## 左右刷新问题

官方当前 put_object_cabinet 的物体采样允许 x 两侧，按物体 x 正负决定抓取臂；柜子接近中央。因此右侧出现本身不构成 bug。训练 clean seed 是专家成功筛选后的子集，可能存在左右成功率偏差；必须统计原始 50 条初始位姿才能确认。

本地 BF16 专家预检查日志有 9 条记录：6 条物体臂 right，3 条 left，缺 seed100001。这里的 plan_success/task_success 是专家预检查结果，不是模型 rollout 的结果。既有成绩为 BF16 0/10、FP32 1/10，尚无增强后成绩。

本地评测代码在专家检查后用同一个 seed 再次 setup_demo；不接受专家失败时才跳到下一 seed，也可能因不稳定跳过 seed。需要同时记录 expert setup 和 policy setup 的初始位姿、资产和随机调用路径，才能区分正常换 episode、相同 seed 重建不一致、训练样本选择偏差。不能把物体世界 x、画面左右、机器人左右臂混用。

## 多模态与动作核对

| 项目 | 代码支持的判断 | 尚需验收 |
|---|---|---|
| RGB/深度/其他视觉 | 调用原生采集器，从新场景重新渲染，无离线 hflip | data_type 配置是否启用；所有实际使用模态是否输出；帧与状态是否同一时刻 |
| 左右相机 | 保留物理相机身份合理，右臂抓物时仍使用 right_camera | HDF5→LeRobot→推理三路键和时间对齐；不能再额外交换相机 |
| 机器人状态/EE/夹爪 | 按新轨迹重新读取，不需人工取负或互换字段 | 与实际 active joint 名称及夹爪开闭范围一致 |
| 14 维动作 | 未离线交换动作；回退按 arm_joints 顺序提取，避免盲用 move_group 索引 | 应是 [L六关节,L夹爪,R六关节,R夹爪]；不能把每臂第七维当成旋转关节。核对转换器的动作时间移位、绝对/增量语义、归一化和反归一化 |
| 双臂职责 | play_once 按变换后物体 x 重新选择物体臂，另一臂开抽屉 | 源/目标 arm_tag 断言、实际接触和动作响应 |
| 语言 | 用新的 {a}/{b} 和资产信息重生成 seen/unseen | 读取实际 instruction；固定的 left/right/方位文本是否仍准确；unseen 是否被误用于训练 |
| 元数据 | scene_info 由新执行生成；报告包含 source_seed | 包内插件的最终 episode 重编号、task_index、来源分组、manifest、保存前后相机/位姿和统计重建未可审计 |

本地既有 LeRobot info.json 将每臂命名为 joint_0…joint_6，这一命名会掩盖夹爪含义。应依据机器人配置和原生 joint_action 字段核实，不能只看 shape=14。当前脚本没有证据证明 LeRobot 转换已跑完。

## 具体风险

1. **不是严格镜像。** map_pose_between_arms 保留姿态 q，仅映射位置；对物体为 x'=0.0085094273-x、y'=y+0.0010041296、z'=z-0.0010002256；柜子 y/z 偏移相反。名义对称平面 x=0.00425471365，但 y/z 也改变，来自 TCP home 而非验证后的机械对称标定。保留姿态对“同一网格换侧重采集”可以合理；不能宣称完整几何反射。det=-1 的反射矩阵也不能直接当四元数旋转使用。
2. **源侧假设未检查。** 物体始终使用 LEFT→RIGHT、柜子始终 RIGHT→LEFT。若源物体已经在右侧，仍会移向左侧；此时固定 home 映射的含义不成立。先统计源位姿，并选择按源臂映射，或定义统一世界平面的位置变换。柜子应根据实际目标场景分布处理，不能因其承担抽屉职责就认定它位于右侧。
3. **专家行为发生改变。** 原 place_actor 被替换为分段 XY 平移、下降、释放，保留抓取姿态。最终物体中心在 XY 上主动停留于目标约 3.5 cm 范围内，高度目标 fp_z+6 cm。当前官方成功检查是位置/高度/夹爪条件，未验证抽屉内稳定支持或碰撞。因此通过条件不证明无穿透、物体已落稳或打开抽屉充分。
4. **IK 回退不保证路径安全。** 只检查末端目标误差，关节线性插值没有显式全程碰撞验收；use_point_cloud/use_attach/constraint_pose 未体现在回退约束中。关节 wrap 后重新检查 FK，却未再次显式验关节限位；采样 IK 分支也需核实限位。velocity 全零与变化的 position 不匹配，应检查执行器语义。成功返回不等于原碰撞规划成功。
5. **multi path 起点风险。** multi_with_fallback 对每个目标使用同一 last_qpos，而非逐段终点更新。其后果取决于原调用方期望的是独立候选还是连续路点，必须检查实际调用语义后再决定修复。
6. **机器人适用范围过宽。** load_args 只检查 embodiment 数量为 1，没有断言必须为 aloha-agilex。硬编码 TCP 和 MPLib 回退不可据此推广到其他机器人/版本。
7. **来源重建不完整。** 同 seed 不等于同 scene：资产列表、模型 ID、配置、机器人与 RoboTwin commit 都需固定。当前 code_hash wrapper 涵盖增强包和 mirror 脚本，未覆盖底层 env/robot/相机/资产与转换器。
8. **报告字段易误读。** mirrored_cabinet_x 在 play_once 后读取，是执行末态而非明确初态；output_episode 在规划通过时便赋值，collection_failure 仍可能保留编号。成功计数应以最终 status、已提交 bundle 与 manifest 交叉核对。

## Leakage 与评测污染

未发现脚本直接读取测试成功标签或测试动作来训练。使用训练 seed 的任务参数生成语言也不是自动构成 leakage。但必须限制 source_seed 为训练来源，原始 episode 与其增强版本不能分到 train/validation 两边；unseen 指令是否允许训练取决于实验协议。

不能把 source_seed、status、stage_success、目标位姿或评测结果加入模型输入。任务正式给出的臂指令是合法条件；如果臂指令来自额外专家求解、且正式评测不提供，则会改变信息条件。

仅保留通过新专家的对侧场景会再次产生成功选择偏差；必须报告分侧/资产的 attempts、accepted 和拒绝原因。不得用新生成器的筛选规则重新过滤正式测试 seed，也不得把自定义 success checker 的成绩当官方成绩。

## 下一步验证顺序

1. 固定原始评测 seed，记录“专家 setup 初态→policy setup 初态→下一 episode 初态”，包含物体/柜子 pose、资产、arm_tag、指令、相机外参、机器人配置和 commit。相同 seed 初态比较应在 settle 后同一阶段完成。先定位是否真的 reset 不一致。
2. 统计训练 50 条与测试初态的左右比例、资产和姿态，并按 object x 分层统计成功率。不要用专家 arm_tag 日志替代物体位姿统计。
3. 取左右各至少 3 个训练源，生成 paired 对侧数据；检查任务演员初态、物理相机身份、关节限位、双臂路径、接触/穿透、速度和夹爪响应。释放后额外仿真 1–2 秒，验证物体稳定留在抽屉且满足官方判据。
4. 从真实增强 HDF5 经正式转换器导出，逐维断言 vector 与左右独立字段一致，核对时间戳、action 时序和归一化统计；用转换后的动作回放，而非只回放规划器 pkl。通过后才扩大生成数量。
5. 同预算比较 baseline、等数量普通新 clean 数据、对侧重采集数据；若新专家/IK不可避免，增加“原侧+新专家”对照以拆开侧变化和专家变化。保持多任务 replay 比例、训练步数和全局采样预算一致。
6. 使用未参与选数据/调参的冻结测试 seeds，原版环境与判据，报告左右分层 SR、总 SR、其他任务退化、attempt 接受率和置信区间；每侧建议至少 50 个 rollout，并用共同 scene/instruction 条件配对。已有10回合只能诊断，不能证明鲁棒性提升。

正式结论可写：已实现仿真中对侧场景重采集，并从代码层面核对多模态一致性路径；严格物理回放与独立闭环泛化验证尚未完成。
